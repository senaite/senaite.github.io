The open source LIMS, from sample intake to published report

SENAITE manages samples, analyses, worksheets, instruments and reports for testing laboratories. Free to use, free to extend, and the code is yours.

How a sample moves through SENAITE

  1. 1Due

    Registered and expected in the lab.

  2. 2Received

    Arrived and checked in. Results can be entered.

  3. 3To be verified

    All results submitted, waiting for a second person.

  4. 4Verified

    Every result confirmed by someone other than the analyst.

  5. 5Published

    The report is generated and sent to the client.

Less manual work

The bench works from worksheets, results arrive from instruments, and the workflow only offers the next step when it is allowed.

Guided workflow
Every sample and analysis follows a defined lifecycle. Transitions appear only when their conditions are met, so steps cannot be skipped by accident.
Instrument results
Results are imported from the files your instruments export instead of being typed in, which removes a transcription step and its errors.
Turnaround time
Each analysis has a due date. Worksheets plan the work at the bench, and late analyses stand out in the listings.

Under control

Who changed what, and when, is recorded on the object itself. Verification by a second person is built into the workflow.

Ready for ISO/IEC 17025
SENAITE supports the process controls an accredited laboratory needs. The accreditation itself stays with the laboratory and how it runs the system.
Audit trail
Every edit of a sample, an analysis or a setup object stores a snapshot with the user, the time and the changed fields. A lab wide audit log can be switched on in the setup.
Dashboard and data access
The dashboard shows throughput over days, weeks and months. Reporting and BI tools read the same data through the JSON API.

Built to run for years

A web application on proven open source infrastructure, with a documented API for everything around it.

Permissions on every object
Roles and workflow states decide who may see or change what, and at which point in the process.
Standard infrastructure
Runs on Linux behind a regular web server or reverse proxy. Several application processes can share one database server as the lab grows.
In the browser
No desktop software to install or update. Any device with a browser works, and IT keeps one central installation.
